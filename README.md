# Overview

The paper proposes HIPPOCAMPUS, an efficient memory substrate for agentic AI. Instead of dense vector databases or knowledge graphs, it uses compact binary token signatures for semantic search and a lossless token-ID stream for exact content reconstruction. Both streams are indexed by Dynamic Wavelet Matrices.

The central claim is that this compressed-domain memory can preserve retrieval quality while reducing search latency and retrieved-token cost. This workspace reproduces the core mechanism on a portable long-memory QA benchmark and scores both accuracy and efficiency constraints.

---

# Problem

Agentic AI systems need persistent contextual memory: past dialogue turns, tool outputs, and user-specific facts must be stored outside the LLM context window and retrieved later when a user asks a related question.

The task in this workspace is long-memory retrieval. Given one multi-session conversation history and a natural-language question about that history, a memory system must return a small set of stored memory entries that contain the answer. The answer-bearing entries are labeled in `data/memory_qa.json`.

A successful system should retrieve the correct entries while keeping the per-query retrieved-token footprint and search work low. The benchmark is intentionally method-agnostic: any system may write retrieval artifacts in the expected JSONL format and run `scripts/evaluate.sh`.

---

# Method

HIPPOCAMPUS stores each memory in two co-indexed streams. The content stream is a lossless sequence of token IDs, stored in a Dynamic Wavelet Matrix (DWM) so entries can be reconstructed exactly with `access(i)`.

The search stream stores one compact binary signature per token. Signatures are generated by sparse random indexing over a local token window, then binarized into fixed-length hash codes. The signature stream is stored in a second DWM.

At query time, salient query tokens are converted into the same binary signature space. The system scans stored signatures with XOR and popcount to perform Hamming-ball retrieval, maps matching token positions back to memory-entry metadata, validates keyword co-occurrence inside entry spans with DWM `rank`, and reconstructs the top entries from the content DWM.

This implementation is from scratch. A web search found the paper and secondary summaries but no public code release.

---

# Evaluation

Run `bash scripts/evaluate.sh <artifact.jsonl> ...` to score one or more retrieval artifacts. Each artifact row must include a question id, answer, `gold_entry_ids`, a method name, and a ranked `retrieved` list of memory entries.

The primary metric is `hit_at_1`, the percentage of questions whose top retrieved entry is one of the labeled answer-bearing entries. Supporting quality metrics are `hit_at_3` and answer-token F1 over the retrieved text.

Constraint metrics measure the paper's efficiency claim: average retrieved-token footprint, average search time, machine-independent bit-operation count, and approximate storage size. Search time is reported for diagnostics only; `avg_bit_operations` is the preferred hardware-independent efficiency metric.
